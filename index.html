Dithered Belief Propagation for Real-Time Quantum Memory Decoding

Zhengyu Cai, Mohamad Ali Jarkas, Bokun Zhao, Warren J. Gross · posted Nov 4, 2026 · quant-ph, cs.IT · arXiv 2611.07144

Overview

A quantum computer can only run long calculations if it corrects its own errors in real time, and the part that decides what to correct, the decoder, has to finish its work in about a microsecond. This paper takes the fastest kind of decoder, belief propagation, which tends to get stuck on modern quantum codes, and unsticks it with two cheap doses of randomness. In simulation, the result roughly matches the best competing decoder while using about 2% of its multiplications.

By the end you'll be able to explain
  • what a decoder is given, what it must output, and why it doesn't need to find the true error;
  • how belief propagation passes messages, derived from Bayes' rule;
  • exactly why it gets stuck on quantum codes, using a two-bit example you can check by hand;
  • the paper's two fixes, why each one works, and what they cost.

1 · THE SETTING

Why decoding has to be fast

Qubits are fragile, so no single physical qubit can hold information for long. The standard answer is to spread each unit of information, a logical qubit, across many physical qubits and to check them repeatedly for damage. The checks are designed so that they never reveal the stored information itself. Each one only reports whether a small group of qubits still has the parity it should. The list of check results is the syndrome, and the algorithm that turns a syndrome into a correction is the decoder.

On current hardware a round of checks takes about a microsecond, and a new syndrome arrives every round. If the decoder takes longer than the stream it is reading, a backlog builds and errors accumulate faster than they are fixed. That is why this paper cares as much about operation counts and clock cycles as about accuracy.

Definition · code parameters

A quantum code labeled [[n, k, d]] uses n physical qubits to protect k logical qubits, with distance d: the smallest number of faults that can change the stored information without setting off any check.

Said another way, d measures how many things must go wrong at once, in exactly the wrong pattern, before the code is fooled.

The paper's main test case is the [[144,12,12]] bivariate-bicycle code, often called the Gross code, which protects 12 logical qubits with 144 physical ones at distance 12. A surface code at the same distance needs a few hundred physical qubits for a single logical qubit, which is why codes like this one, called qLDPC codes (quantum low-density parity-check), attract so much attention. Each check touches only a few qubits, but the checks are wired across the device in a tangle of short loops. Section 5 shows why those loops are a problem.

proofA distance-d code corrects up to ⌊(d − 1)/2⌋ faults. Why?

Suppose the true error has t faults, with 2t < d. Any other error that produces the same syndrome but acts differently on the stored information must differ from the truth by a pattern that trips no check and changes the information, and by the definition of distance that pattern has at least d faults. So the other error has at least d − t faults, which is more than t. A decoder that always chooses the lightest explanation therefore never picks one with the wrong effect. The largest t with 2t < d is ⌊(d − 1)/2⌋, which is 5 for the Gross code.

∎

In short: a decoder reads parity checks, never the data, and must keep up with a new syndrome every microsecond.

2 · THE PROBLEM

What the decoder is given, and what it must return

To state the decoding problem precisely, we need three ingredients: a list of the things that can go wrong, a record of which checks each one sets off, and a rule for what counts as a correct answer.

Faults and the parity-check matrix

A fault is one specific thing that can go wrong anywhere in the circuit: a qubit flipping, a gate misbehaving, a measurement reporting the wrong value. Number the possible faults 1 to n. An error is then a vector E in {0,1}ⁿ, where Ej = 1 means fault j happened. The parity-check matrix H has one row per check and one column per fault, and Hij = 1 exactly when fault j trips check i. The syndrome is the vector of check results,

The arithmetic is mod 2 because a check reports parity: two faults on the same check cancel, so 1 + 1 = 0. Read the equation column by column. Column j of H is fault j's signature, the set of checks it trips, and σ is the mod-2 sum of the signatures of every fault that happened. Decoding means working backward from that sum to a set of columns that produces it.

Under circuit-level noise, every gate and measurement over several rounds of checking is a possible fault, and faults with identical signatures are merged. For the Gross code that makes H a 1,872 × 71,280 matrix: about 38 possible explanations for every clue.

What counts as success

Here quantum decoding departs from intuition. The decoder does not have to find the error that actually happened. Its guess Ê only has to explain the syndrome, and the leftover pattern E + Ê has to leave the stored information alone:

Eqs. 4 and 5

The matrix A records how a pattern acts on each logical qubit. When several different guesses are all acceptable, the code is called degenerate, and sparse quantum codes are highly degenerate. The failure case is a logical error: the guess explains every check, yet the leftover changes the stored information, with no trace in the syndrome.

proofThe leftover never trips a check. Why?

Write R = E + Ê. Because multiplication by H is linear, HR = HE + HÊ = σ + σ = 0 mod 2. So as long as the guess explains the syndrome, the leftover is invisible to every check. Invisible patterns come in two kinds: those that act trivially on the stored information, which are harmless, and those that act as a logical operation, which are logical errors. The distance d is the weight of the lightest pattern of the second kind.

∎

Both running examples show this. In the chain, the only invisible patterns are 00000 and 11111, and 11111 flips the stored bit. If the true error is 10101, the lighter explanation 01010 matches every check, and the leftover is 11111: a logical error that no decoder could have avoided, because the lighter explanation really is more likely. In the trap, both checks look at both bits and both fire. Exactly one bit must have flipped, but nothing says which, so 10 and 01 are equally light. The trap is a classical cousin of a two-qubit quantum code studied by Poulin and Chung, where the two analogous corrections differ by a harmless pattern, so either one is correct. Here we simply treat 10 and 01 as equally good. Keep that symmetry in mind; it is the whole story of Section 5.

In short: given σ = HE, find a light Ê with HÊ = σ whose leftover E + Ê doesn't touch the stored information. The exact error is not required.

4 · BELIEF PROPAGATION

Checks and faults pass notes until they agree

Finding the lightest Ê exactly is too slow, so decoders approximate it. Belief propagation (BP) approximates it locally. It runs on the Tanner graph, which has one node per fault, one per check, and an edge wherever Hij = 1. In each round, every check tells each of its faults what the other faults on that check imply about it. Then every fault adds those messages to its prior and reports back. Once beliefs stop changing, the decoder blames every fault whose belief is negative.

The paper uses the Min-Sum version of BP. A check i sends fault j a sign and a size:

Eqs. 8 and 9

The sign is the parity of the other faults' current guesses, flipped if the check fired. In words: if the check fired and everyone else looks fine, you are probably the culprit. The size is the confidence of the least confident other fault, because a parity is only as certain as its shakiest member. Each fault then combines its evidence:

Eqs. 10, 11 and 12

The message back to check i leaves out what check i said, so no check hears its own opinion echoed back as new evidence. Lj includes everything and is the belief used for the decision.

derivationWhere do Eqs. 8 and 9 come from?

Start from the exact answer. By Section 3, a fault with belief m has 1 − 2p = tanh(m/2), and 1 − 2p is the expected value of (−1)x for a bit that is 1 with probability p. For independent bits, expected values of products multiply, so the expected value of (−1) raised to the parity of several bits is the product of their tanh terms. Check i says that fault j equals σi plus the parity of the other faults, mod 2. Therefore

This is the exact check message, called the tanh rule. Min-Sum simplifies it in two steps. Since tanh(m/2) has the same sign as m, the sign of the product is (−1)σ times the product of the signs, which is Eq. 8. Since every |tanh| is below 1, the product is controlled by its smallest factor, and keeping only that factor gives the minimum of the sizes, which is Eq. 9.

With two other faults at 2.2 and 3.0, the exact rule gives 2 artanh(tanh 1.1 · tanh 1.5) ≈ 1.83 while Min-Sum gives 2.2. Multiplying by extra factors below 1 can only shrink the product, so Min-Sum is never less confident than the exact rule. That overconfidence is part of why it can overshoot. In return, hardware needs only sign comparisons and a minimum: no tanh, no multiplier.

∎

Fact · BP is exact on graphs without loops

If the Tanner graph is a tree, BP's beliefs equal the true probabilities once messages have crossed the longest path. That is why the chain settles by round 4.

proof sketchWhy exactly on a tree?

The tanh rule assumed that the other faults on a check are independent. On a tree, cutting any edge splits the graph into two separate pieces, so the evidence arriving from one side shares nothing with the evidence from the other. Each message is then an exact summary of everything on its side, and Section 3 says independent evidence adds. By induction on distance from the leaves, every message is exact after enough rounds. A loop breaks the induction: two neighbors of a check can both depend on the same fault further around the cycle, so their evidence is counted twice.

∎

In short: checks send "sign = parity of the others, size = the weakest of them"; faults add; negative means blame. On a tree this is exact.

5 · THE FAILURE

Why BP gets stuck on quantum codes

Classical LDPC codes can be designed with few short loops, and BP works very well on them. Quantum codes can't avoid them. The checks of a quantum code have to be compatible measurements, and Poulin and Chung showed in 2008 that this requirement forces every quantum code's Tanner graph to contain loops of length four. Sparse quantum codes are also highly degenerate. Together these produce a failure that the chain could never show, and the trap shows it in its smallest form.

whyWhy must quantum codes contain 4-loops?

This is Poulin and Chung's argument, sketched. A 4-loop exists when two checks share two or more qubits, so suppose every pair of checks shares at most one. Quantum checks must commute, and two checks that overlap on a single qubit only commute if they apply the same type of operation there. Following this around a qubit forces every check on that qubit to be of one type, say Z. A Z error on that qubit then commutes with every check and sets nothing off, so the code can't detect it. That breaks the code unless the qubit is trivially decoupled. So a useful quantum code has 4-loops.

∎

In the trap, both checks connect to both bits, so the Tanner graph is a single 4-loop: bit 1, check 1, bit 2, check 2, back to bit 1. Both checks fire. Work through BP by hand with both priors at λ = 2.20.

Round 1. Each check tells bit 1 "the other bit looks fine and I fired, so it's you": −2.20, twice. Bit 1's belief is 2.20 − 2.20 − 2.20 = −2.20. By symmetry, bit 2 gets the same. The guess is 11, which trips neither check, because each check now sees two flips. It fails.

Round 2. Bit 1 sends each check its total minus that check's message: −2.20 − (−2.20) = 0. Every message is now 0, so the checks send back 0, and both beliefs return to the prior 2.20. The guess is 00, which also fails.

Round 3 is round 1 again. BP alternates between 11 and 00 forever, never landing on 10 or 01, because nothing in the computation distinguishes bit 1 from bit 2. A correct answer requires treating two identical bits differently, and BP, which treats them identically, can't.

Animation · the trap, plain BP

Real codes show the same behavior on a larger scale. Around each 4-loop, messages return to where they started and are counted again, and Min-Sum's overconfidence amplifies them. Wherever two equally light corrections exist, the faults where they differ receive votes in both directions. Beliefs swing between rounds, split evenly, or stall near zero, and the decoder never produces a guess that explains every check. The paper names loops, symmetries and degeneracy as the causes. Poulin and Chung's own remedy was to break the symmetry by randomly perturbing the priors, and the paper builds on that idea.

In short: 4-loops recycle messages, and degeneracy gives BP ties it has no rule to break. The trap oscillates between 11 and 00 forever.

6 · FIX ONE

Damping messages that flip sign

The paper's decoder, which it calls qDither, starts as ordinary Min-Sum and adds two mechanisms. The first targets the swinging directly. In each round, a randomly chosen fraction ρ of faults follow an extra rule: if a fault's outgoing message has the opposite sign from the previous round, add the previous message to it. Messages that keep their sign pass through unchanged.

Eqs. 16 and 17

Here ℓ is the round. The product of the two signs is +1 when they agree and −1 when they don't, so δ is 0 or 1: an indicator for "the sign flipped," written as arithmetic. For example, suppose the previous message was +3 and the new one is −2. Then δ = (1 − (−1)(+1))/2 = 1 and m″ = 3 + (−2) = +1. The message still moves toward the new evidence, but a swing of five units shrinks to two. On the Gross code, ρ = 0.65.

whyWhy this form, and where did the randomness go?

In hardware, the product of two signs is the XOR of two sign bits, so the rule costs one XOR, one multiplexer and one adder, with no multiplication. The classical trick it replaces (the paper's Eq. 14) multiplies messages by a random −1 with probability ρ, which shakes BP out of a rut but requires a random number generator inside every node. qDither keeps ρ only to choose which faults use the damper; the damper itself is deterministic. That is the basis for the paper's claim of eliminating node-level random number generators.

The authors also note a trade-off. A larger ρ calms the dynamics, but it also makes successive runs behave more alike, which weakens the restarts in Section 7.

In short: when a message flips sign, add back the previous one. That's one XOR and one addition, and it softens oscillation.

7 · FIX TWO

Restarting from a nearby place

Damping softens swings but can't break an exact tie, because the trap's two bits would still be damped identically. The second mechanism supplies the asymmetry. Two more details complete the method. Each run gets a fixed budget, 15 iterations on the surface code with up to 3,000 runs and 100 on the Gross code with up to 1,500, and the decoder stops at the first valid guess. In practice very few runs are needed: in the paper's cost example, the average is about 2.6. The surface-code variant labeled qDither-BP-5 instead collects up to five different valid guesses and returns the one with the smallest Σ λjÊj, the most likely explanation from Section 2.

whyWhy allow a negative blend weight?

(1 − χ)a + χb is the point a fraction χ of the way from a to b. With χ between 0 and 1 the new start lies between the prior and the failed ending. With χ below 0 it lies past the prior, on the side away from the failure. For example, with λbase = 2.2, q = −1.4 and χ = −0.1, the start is 1.1(2.2) − 0.1(−1.4) = 2.56: more confident than the original prior and pointed away from where the failed run went. That lets the chain back out of a bad direction instead of moving further into it. The paper's ranges were [−0.14, 0.85] for the surface code and [−0.07, 0.5] for the Gross code. The classical version of the trick (Eq. 15) adds plain random noise to the prior instead of reusing what the failed run learned.

In short: each restart starts every fault from its own random point between the prior and the last failure. Different weights break ties, and BP amplifies the difference until it escapes.

8 · RESULTS

What the simulations show

All results are simulations under circuit-level noise. The authors tested a distance-11 rotated surface code and the Gross code, against four baselines: plain BP; BP+OSD, which falls back on a costly Gaussian elimination when BP fails; Relay-BP, IBM's memory-based BP variant and the main rival; and, on the surface code, minimum-weight perfect matching (MWPM), the standard surface-code decoder. 9 · ASSESSMENT

What is shown, and what isn't yet

The contribution is clear and well supported in simulation: two old classical ideas, random sign flips and random restarts, reshaped so that they suit quantum codes and cheap hardware. The headline claims, though, are narrower than the abstract makes them sound. "98% fewer multiplications" counts only the setup of each restart and depends on the average of 2.6 runs, which changes with the noise level. "No node-level random number generators" describes one proposed hardware unit, but the algorithm as written still draws a random blend weight and a random selection coin for every fault, and the hardware is described but not built. Every setting was tuned on 1,000 samples at a single noise level, p = 0.005.

The deepest open question is why dithering works. The paper shows that it does, but it doesn't analyze which loop and degeneracy structures trap BP on real codes, or how often a restart escapes. The trap gives the mechanism in miniature: a tie, a random asymmetry, and BP amplifying it. Whether that picture explains the Gross code is unproven. The authors list hardware architectures, cheaper hyperparameter tuning and more code families as next steps.

In short: a promising, cheap decoder with strong simulations, an unbuilt hardware story, and no theory yet for why it works.

1 · THE SECRETARY PROBLEM

Picking the best when you can't go back

The whole paper generalizes one classical puzzle, so it pays to understand that puzzle completely first. The question is how well anyone can pick the single best item from a stream when each item must be accepted or rejected the moment it appears.

Definition · the secretary problem

Here n distinct values arrive in uniformly random order. After seeing each value, an algorithm must immediately and irrevocably accept or reject it, and it may accept at most one. It succeeds if it accepts the largest value.

In words: you interview candidates one by one, you can only compare them with the people already seen, and a rejected candidate is gone for good.

2 · MATROIDS

Rules for which sets you may keep

Many real selection problems let you keep more than one item, but not just any combination: a hiring budget, a ban on redundant network links, a limit per department. A matroid is the most general kind of rule under which "take the best things that still fit" is always optimal, which makes it the natural setting for asking whether choosing many is harder than choosing one.

Definition · matroid

A matroid is a finite ground set V together with a family 𝓘 of subsets, called independent, such that the empty set is independent, every subset of an independent set is independent, and the exchange property holds: if A and B are independent and |A| < |B|, then some b in B but not in A makes A ∪ {b} independent.

In words: the allowed sets are closed under throwing things away, and a smaller allowed set can always be grown using something from a bigger one.

This axiom list is the standard textbook definition, added here as background. The paper assumes it and works with the derived notions below.

Three examples carry the whole chapter. The rank-one matroid allows any set of size at most one, which is exactly the secretary problem. The uniform matroid Uk,n allows any set of at most k of the n elements. The graphic matroid of a graph takes the edges as the ground set and calls a set of edges independent when it contains no cycle, that is, when it is a forest. The four-town network is the graphic matroid of the complete graph on four vertices.

The paper uses a few derived notions. The rank of a set T is the largest size of an independent subset of T. An element is spanned by T if adding it does not raise the rank, and the closure cl(T) is the set of all elements T spans. In the network, the full rank is r = 3, because a forest on four towns has at most three roads. The set {ab, bc} spans ca, since adding ca closes the triangle a, b, c without connecting anything new.

proofDo forests really satisfy the exchange property?

This check is ours, as background. A forest with k edges on a fixed set of N vertices has exactly N − k connected components, because each edge that creates no cycle merges two components. If A and B are forests with |A| < |B|, then A has more components than B. Some edge of B must therefore join two different components of A, since otherwise every component of B would sit inside a component of A, and B would have at least as many components as A. Adding that edge to A merges two components and creates no cycle.

∎

In short: a matroid says which sets are allowed; rank one is the secretary problem, and graphic matroids are "no cycles".

3 · GREEDY

Why greedy is optimal, and the one-element swap

If every value is known in advance, the best independent set is easy to find. The interesting question is how that best set reacts when one element is added, because an online algorithm sees elements one at a time and every arrival is such an addition.

Definition · Greedy(T)

The set Greedy(T) is built by scanning the elements of T in decreasing value, with ties broken by a fixed order of labels, and keeping each element that leaves the kept set independent. The paper calls Greedy(V) the canonical optimum.

In words: take the most valuable thing that still fits, and repeat.

Among all downward-closed families, matroids are exactly the ones for which greedy is optimal for every nonnegative choice of values, a classical theorem the paper cites. On a graph, greedy is Kruskal's algorithm for a maximum spanning tree. In the network it keeps ab (6) and bc (5), skips ca (4) because ab and bc already connect a to c, keeps ua (3), and then skips ub and uc because all four towns are already connected. That gives Greedy(V) = {ab, bc, ua}, worth 14.

The paper uses three properties of greedy, all standard.

Fact · Lemma 2.1

(i) An element of Greedy(V) stays in Greedy(T) for every subset T that contains it. (ii) Adding one element e to T changes Greedy(T) in one of three ways only: no change, e joins, or e joins and exactly one old element f leaves. (iii) Changing one element's value either leaves the greedy set alone or swaps that element with exactly one other.

proofWhy can adding one element push out at most one old element?

An element is kept by greedy exactly when the elements scanned before it do not span it. For (i), shrinking the ground set can only remove elements scanned before e, and a smaller set cannot span what a larger set did not.

For (ii), inserting e into the scan only adds a predecessor to some old elements, so no old element can newly enter greedy; the only possible newcomer is e. Greedy returns a largest independent subset, and the ranks of T and T + e differ by at most one. So the new greedy set either equals the old one, adds e, or adds e and loses exactly one old element. Part (iii) follows the same way: raising e's value can only bring e in and push others out, and both greedy sets have the same size, so any change is a single swap.

∎

The element f in part (ii) is called e's exchange partner. Take T = {ab, bc, ub} in the network. Greedy keeps all three, a spanning tree. Now insert ua, worth 3. Greedy keeps ab, bc, then ua, which connects u, and then rejects ub, which would close the loop u, a, b. So inserting ua displaced exactly one element, its exchange partner ub.

In short: greedy is optimal on matroids, an optimal element stays optimal in any subset, and each insertion displaces at most one exchange partner.

4 · THE CONJECTURE

Is choosing many harder than choosing one?

With the pieces in place, the online problem can be stated precisely, along with the two ways of measuring success that the paper uses.

Definition · matroid secretary problem

The n elements arrive in uniformly random order. On each arrival the algorithm sees the element and its value and must accept or reject it irrevocably, and the accepted set must always be independent. Only n is known in advance. Independence can be tested only on sets of elements already seen. An algorithm is c-competitive if its expected value is at least 1/c times v(Greedy(V)), and c-probability-competitive if it accepts every element of Greedy(V) with probability at least 1/c.

In words: build the best forest, or the best team, from a random stream, and the score is either expected value or each optimal element's chance of being taken.

Babaioff, Immorlica and Kleinberg asked in 2007 whether some constant c works for every matroid. That is the matroid secretary conjecture; its strong form asks for c = e, matching rank one. The general guarantee improved from O(log r) to O(√log r) and then to O(log log r), where it had stood since 2014. Constant guarantees were known only for special classes, such as graphic, laminar and transversal matroids.

Why the obvious rule fails

The natural idea is to copy the secretary rule: reject about half the arrivals as a sample S, then accept a later element e whenever e ∈ Greedy(S ∪ {e}). Lemma 2.1 (i) promises that every optimal element outside the sample passes this test, so the value looks good. The trouble is that the accepted set need not be independent. The paper's Appendix A shows this on the network itself. Suppose the sample is the three spokes ua, ub, uc and the real arrivals are the triangle ab, bc, ca. For ab, greedy on the spokes plus ab keeps ab, ua and uc, so ab passes. By the same check bc and ca pass. The rule accepts all three sides of the triangle, which is a cycle.

Repairing the rule by keeping a running independent set that contains all acceptances also fails, as the paper's "hat" examples show: accepting one cheap edge can make a later, very valuable edge impossible. The paper's technical overview names the real obstacle. When an optimal element e is inserted, it displaces at most one partner f. If f were fixed independently of the random order, e would come before f with probability 1/2 and could be accepted safely. But the partner depends on the algorithm's state, and the state depends on the order.

In short: the goal is a constant for every matroid, ideally e; testing each arrival against a sample can accept a cycle, and the exchange partner moves with the order.

5 · REVERSIBLE UPDATES

An algorithm whose bookkeeping can run backward

The paper's first algorithm, Algorithm 1, keeps a reference set whose greedy solution always contains everything accepted, and it updates that set in a way that can be undone. This section describes the algorithm and why it never builds a cycle; the next section shows why it accepts optimal elements often enough.

The algorithm

First, draw n fair bits X1, …, Xn and let K be the number of ones. Reject the first K arrivals and store them as the sample S. The remaining arrivals are real. The algorithm keeps a configuration C, starting at C = S, and a set F of processed elements, starting empty. It then makes n processing steps. At step i, if Xi = 1 it takes the next stored sample element, and otherwise the next real arrival. Either way, call the element e and propose C′ = C ⊕ e: a sample element is proposed for deletion from C, a real arrival for insertion.

Definition · the preservation test

In words: the update is allowed only if every element processed so far keeps its greedy status, in or out.

If the test passes, the algorithm accepts e when e ∈ Greedy(C′), and in any case replaces C by C′. It updates even when it does not accept. Finally it adds e to F. A sample element is always being deleted, so it is never in C′ and is never accepted.

Fact · Lemma 2.3

After every step, ALG ⊆ Greedy(C) ∩ F. In particular, the accepted set is always independent.

proofWhy can an accepted element never be pushed out later?

The inclusion holds at the start, when ALG and F are empty. If a step's test fails, C and ALG do not change and F only grows. If it passes, every earlier acceptance is in F, and the test says its greedy membership does not change, so it stays in the greedy set. A new acceptance lies in Greedy(C′) and is then added to F. Greedy sets are independent, and so is every subset of one.

∎

The second ingredient is that updates happen even after rejections. Appendix A explains why: if the reference set changed only on acceptances, sample elements would never be removed, and on a uniform matroid the algorithm could get permanently stuck with many unused slots, accepting only on the order of √r elements by the authors' heuristic estimate. Deleting sample elements as they are processed frees room for later real arrivals.

6 · THE SNAPSHOT LEMMA

Why each optimal element is taken with probability 1/4

Section 4 ended with the obstacle: an optimal element is safe if it comes before its exchange partner, but the partner depends on a state that depends on the order. The paper's key idea is to show that the state an element sees is, in distribution, completely unrelated to the order.

Reversibility

Look at one step with a fixed element f and fixed processed set F. The test compares Greedy(C) ∩ F with Greedy(C ⊕ f) ∩ F. Starting from C ⊕ f instead of C, the test compares the same two sets in the other order, so it gives the same answer. If it passes, C goes to C ⊕ f and C ⊕ f goes to C; if it fails, both stay put. Each step therefore pairs up configurations and swaps or fixes each pair, which is a bijection on the 2n subsets of V that is its own inverse.

On the network, take F = {ub} and the sample step f = ab. From C = {ab, bc, ub}, deleting ab leaves ub in the greedy set, so the test passes and C becomes {bc, ub}. From {bc, ub}, toggling ab would add it back, ub would again stay in, and the test would pass the other way. The step simply swaps these two configurations.

Fact · Lemma 2.4 and Corollary 2.5

Fix an element e and a processing order. For every T ⊆ V exactly one initial sample S produces the snapshot Ce = T. Consequently Ce is a uniformly random subset of V, independent of the processing order.

proofHow can a random sample stay uniformly random after all those updates?

With the order fixed, every step before e is one of the self-inverse bijections above, so their composition is a bijection from initial samples to snapshots. Each T therefore comes from exactly one S. To run it backward from a configuration D after a step with element f, compare Greedy(D) ∩ F with Greedy(D ⊕ f) ∩ F: if they agree the predecessor was D ⊕ f, otherwise it was D.

For the corollary, fix T and a permutation π. Exactly one S0 gives Ce = T under π. Exactly one choice of bits and arrival order produces the pair (S0, π): the bits are Xi = 1 when π(i) ∈ S0, and the arrival order lists S0 first, then the rest, each in its order within π. proofWhere do the two factors of 1/2 come from?

If inserting e displaces nothing, the test passes. Otherwise Lemma 2.1 (ii) gives a unique partner f with Greedy(T + e) = (Greedy(T) − f) + e. The test passes exactly when f has not been processed yet, that is, when e comes before f. The partner is determined by T, and by Corollary 2.5 the order is still uniform given T, so e comes first with probability 1/2. Either way, Pr[e ∈ ALG | Ce = T] ≥ 1/2. Finally, e ∉ Ce exactly when e ∉ S, which has probability 1/2. Averaging gives at least 1/4.

On the network, take e = ua with snapshot T = {ab, bc, ub}. Section 3 found its partner: ub. If ub has already been processed, inserting ua would change ub's status and the test fails; if ub is still unprocessed, ua is accepted. Given the snapshot, each of these has probability 1/2.

In short: because every update can be undone, the state an element sees is a fresh uniform random set, independent of the order; that fixes the exchange partner and leaves a fair coin for who comes first.

The survivor distributions

The target comes from Eq. 11. Call an arrival eligible if the larger elements seen so far do not span it, the matroid version of "best so far". The plan is to accept each eligible arrival at time t > p with probability p/t. By Lemma 2.1 (i) every optimal element is eligible whenever it arrives, so it would be accepted with probability p ln(1/p), which is 1/e at p = 1/e. The hard part is doing this while keeping the accepted set independent, and the paper's answer is an offline experiment.

Definition 5.1 · survivor experiment

For an ordered set O and horizon t ∈ [p, 1]: give each element an independent auxiliary time uniform on [0, t] and call it early if that time is at most p. Let its capped spanning time σe be the first moment u ∈ [p, t] at which the larger elements already present span e, or t if that never happens. Each early element survives independently with probability ln(σe/p); late elements never survive.

In words: sample about a 1/e fraction, then let each sampled element live with a probability that grows the longer it stays unblocked by bigger elements.

At horizon 1 an optimal element is never spanned by larger ones, so σe = 1, and with p = 1/e its survival probability when early is ln(e) = 1. Optimal elements therefore survive independently, each with probability exactly 1/e. Any survivor lies in the greedy set of the early sample, so the survivors are always independent.

8 · THE PROPHET VERSION

One sample per distribution is enough

The secretary model assumes a random order but knows nothing about values. The prophet model flips this: values are random draws, independent across elements, and arrive in any fixed order. The question here is how much information about the distributions an algorithm needs.

Definition · single-sample prophet inequality

Each element's value Re is drawn independently from an unknown distribution, and before arrivals the algorithm receives one independent sample Se from each. The order is fixed in advance, independent of everything else. The benchmark is the expected optimum E[max over independent I of the sum of Re].

In words: you have seen one past value of each item and must do well against someone who sees the future.

Algorithm 2 keeps one value per element, initially its sample. When e arrives, it proposes swapping in e's real value. A fair coin decides, unless the swap would knock a processed element f out of the greedy set: then f's past decision rules, so an accepted f blocks the swap and a rejected f forces it. The arrival is accepted when the swap happens and e is in the new greedy set.

Fact · Theorem 3.1

More strongly, the accepted elements and values are distributed exactly like a fresh draw's greedy optimum with each element kept independently by a fair coin. The ratio 2 is optimal even for one item with known distributions.

The proof follows the same template as Section 6, with exchangeability replacing reversibility: a sample and a real value are two independent draws from the same distribution, so they can be generated as an unordered pair with a fair coin deciding which is which. Before this paper, constant ratios for general matroids needed polylogarithmically many samples per distribution.

A connection, oursProphet inequalities are optimal-stopping results, the same family as deciding when to exercise an American option or sell an asset. A rank-one prophet inequality says a simple threshold captures half of what perfect foresight would; the matroid version extends that to portfolios of choices with structure. The paper doesn't discuss finance.

In short: with one sample per distribution and a coin-plus-override rule, the accepted set is exactly half of a fresh optimum, matching the best possible ratio 2.

10 · ASSESSMENT

What is shown, and what isn't yet

This is a merged and extended version of three preprints from September 2026, by Singla, by Abdi, Banihashem, Hajiaghayi and Mittal, and by Huang, and it claims to settle a problem open since 2007. The 1/4 argument of Section 6 is short, complete and checkable; it uses only Lemma 2.1 and a counting argument, and our exhaustive run on the network agrees with every step of it. The prophet result has a similarly self-contained proof. The 1/e result rests on a much longer chain: the realization theorem, the capacity induction of Lemma 5.3 with background schedules, and the forward and reverse procedures behind the efficient algorithm. Those parts are proofs in the paper, but they are new, long and not yet peer reviewed.

Several claims are narrower than a quick read suggests. The efficient 1/e algorithm runs in expected polynomial time in a real-number model with exact arithmetic and unit-cost ln and exp, not a bit-complexity bound. The prophet result assumes the order is fixed independently of the samples and values; a stronger adversary that sees everything is not covered, and the paper notes later work on that case. The finite-size improvement over 1/e is proved only for linear matroids known in advance, and the evidence beyond them is floating-point LP solutions, which the authors call observations rather than certificates. The intersection and submodular bounds are large constants, not tight.

The paper is also unusually explicit about its process. Its methodology statement says that AI models were used in obtaining the main algorithmic guarantees, including Theorems 2.2, 3.1, 7.2 and 5.2, that the LP and its computations were done without AI, that the exposition was drafted with AI help, and that the authors checked all arguments. It also reports concurrent work: the linear-matroid result was found independently by others, and building on Singla's preprint, Chan, Lin and Wang improved the plain competitive ratio from 4 to about 3.1462.

In short: the 4-competitive and prophet proofs are short and convincing; the optimal e result is a long new proof awaiting review, with efficiency stated in an idealized model.

1 · THE COUPON COLLECTOR

How long until you've seen everything?

The paper's process is a graph version of a classical puzzle, and its main tools are refinements of the classical solution, so it is worth having that solution in hand. The question is how many random draws it takes before every type has appeared.

Definition · coupon collector

There are m coupon types. Each draw is uniform over the m types and independent of all other draws. The collection time is the number of draws until every type has appeared at least once. More generally, Dm,d is the number of draws until every type has appeared at least d times.

2 · THE GRAPH VERSION

Coupons you collect through your neighbors

Alon asked what happens when a random draw can only help in a limited, local way. Motivating examples in the literature include peer-to-peer networks, where a random node can only pass something to a neighbor. The question is how the shape of the graph changes the collection time.

Definition · the covering process and cc(G)

Let G be a finite simple graph with no isolated vertices. All vertices start uncovered. At each step a vertex v is sampled uniformly at random, independently of earlier steps. If v has uncovered neighbors, one of them, chosen uniformly, becomes covered; otherwise nothing happens. The sampled vertex may itself be covered or uncovered. The number of steps until every vertex is covered is NG, and cc(G) = E NG.

In words: each vertex you pick hands a coupon to one random neighbor that still lacks one, and a pick is wasted when all its neighbors are already done.

The triangle can be done completely by hand. While two or more vertices are uncovered, every vertex has an uncovered neighbor, so the first two steps always succeed. Then one vertex w is left. Our reading of the intuition comes from the triangle: in a clique the last vertex can only be reached from its d neighbors, so the final covering waits a long time. Alon also suggested the uniform estimate cc(G) ≤ n + O((n log n)/d), which the paper numbers (31) and also disproves.

In degree two the question is concrete. Every 2-regular graph is a disjoint union of cycles, a standard fact we add as background, so for n divisible by three the conjecture says that disjoint triangles are slowest.

In short: each sampled vertex covers one random uncovered neighbor; cc(K3) = 7/2, the square is the two-type double coupon collector, and Alon conjectured that cliques are slowest.

3 · POISSON CLOCKS

Turning one sequence into independent pieces

In discrete time the components of a disjoint union are tangled together: a step spent on one triangle is a step not spent on another. The paper removes that coupling by moving to continuous time, where the components run independently and the finishing time of the whole graph becomes the maximum of the components' times.

Definition · exponential variables and Poisson clocks

A random variable X ~ Exp(λ) has P(X > t) = e−λt for t ≥ 0, and mean 1/λ. A rate-λ Poisson clock rings at times whose gaps are independent Exp(λ) variables, so the number of rings by time t is Poisson with mean λt.

In words: a clock that is equally likely to ring in any short instant, no matter how long it has already waited.

5 · TWINS AT THE FINISH

What controls the slow end of the process

The expected finishing time of a big union is dominated by its slowest component, so what matters is how likely one component is to still be unfinished after a long time. The paper identifies exactly which feature of a graph sets that probability.

When the uncovered set is U, a ring is useful exactly when it comes from a vertex adjacent to something in U. So the total rate of the next covering is |N(U)|, the number of vertices with a neighbor in U, and this is at least the minimum degree δ. It equals δ only when all of U sits inside one group of degree-δ vertices that share the same open neighborhood. Call such vertices twins; the word is ours, the paper speaks of equivalence classes of equal open neighborhoods.

Definition · τδ(G)

Partition the vertices into classes with identical open neighborhoods. For a graph with minimum degree δ ≥ 1, τδ(G) is the size of the largest class consisting of degree-δ vertices. For a d-regular graph, τ(G) = τd(G).

In words: the largest number of minimum-degree vertices that all have exactly the same neighbors.

In the triangle every vertex has a different neighborhood (vertex 1 sees {2, 3}, vertex 2 sees {1, 3}), so τ = 1. In the square, vertices 1 and 3 both see {2, 4}, so τ = 2. When the last uncovered vertices are twins, each covering has to wait at the slowest possible rate δ, and twins can force several such slow waits in a row.

The degree-two results are complete and, by the standards of the field, elementary: Poissonization, an exact rate identity, a backward duality on cycles, and power-series coefficient comparisons. The twelve-vertex counterexample is a finite computation and is easy to trust; our independent rational-arithmetic solution of the 4,096-state chain reproduces both of the paper's fractions exactly, and also confirms C6 and 2C3 tie and that C4 ⊔ C5 beats 3K3. The full classification rests on Lemmas 3.1 to 3.3, which are compact but careful; we checked the generating-function formula only for m = 2 and 3, and the inequalities numerically at four times, not in general.

Several claims are narrower than the headline. In degree d ≥ 3 the paper does not find the slowest graph at each order. Theorem 4.4 identifies Kd,d unions as optimal only among graphs whose components have bounded size L and only for n beyond an unspecified threshold depending on d and L, so a graph with one huge component is not covered. Proposition 5.1 disproves the conjecture only for large n, with an unspecified Od(n) error, and does not say where the crossover is. Graphs that are not regular are outside the scope except for Theorem 4.1, which applies to any graph with minimum degree at least one.

The paper states that the authors used a large language model during preparation, for mathematical exploration, checking arguments, organization and language editing, and that the authors take responsibility for the statements and proofs. It is a fresh preprint and has not been refereed.

A connection, oursThe mechanism in Section 5 is general: when a process ends with several items that can only be served by the same bottleneck, the waiting times stack and the tail picks up a polynomial factor. The same thing makes a sum of k exponential service times (an Erlang distribution) far more likely to run long than a single exponential with the same rate. The paper doesn't make this connection.

In short: degree two is settled completely and verifiably; higher degree is settled only asymptotically and within bounded component sizes.

Exact (Non-)Accelerations of Heavy-Ball Discretizations

Overview

Two momentum methods can follow the same differential equation in the limit and still behave completely differently: one converges fast on every smooth convex bowl, the other can circle forever on some of them, and the deciding quantity is whether the gradient is evaluated at least half a step ahead of the current point. This paper makes that precise for the whole family of two-step momentum methods that includes Polyak's heavy ball, Nesterov's accelerated method and the triple momentum method. It computes the exact worst-case speed of each method when the problem is badly conditioned, finds that the answer is the smaller of two numbers, θ/3 and a quadratic constant, explains where the 1/3 comes from, and shows that any method that looks less than half a step ahead cannot be accelerated on general functions.

  • how a momentum method with β close to 1 turns into a damped oscillator, ẍ + θẋ + ∇F(x) = 0, and why its speed on quadratics is the constant cQ;
  • the energy argument that limits the oscillator to the rate θ/3 on non-quadratic functions, and the spiraling trajectories that show θ/3 cannot be beaten;

1 · GRADIENT DESCENT AND THE CONDITION NUMBER

Why is a narrow valley slow?

Everything in the paper is measured against plain gradient descent, so it is worth seeing exactly why gradient descent is slow and what number controls it. The answer is the ratio between the steepest and the flattest curvature of the function.

Definition · the class 𝓕μ,L and the condition number

A differentiable function f belongs to 𝓕μ,L, with 0 < μ < L, when f(x) − (μ/2)‖x‖2 is convex and the gradient is L-Lipschitz, ‖∇f(x) − ∇f(x′)‖ ≤ L‖x − x′‖. The condition number is κ = L/μ.

In words: f is a bowl that curves upward at least as fast as μ and at most as fast as L in every direction, and κ measures how elongated the bowl can be.

For a quadratic the curvatures are literally the eigenvalues. Take f(x) = ½ Σi λixi2 with μ ≤ λi ≤ L. The gradient has coordinates λixi, so one step of gradient descent with step h acts on each coordinate separately,

The function λ ↦ |1 − hλ| is a V-shape with its zero at λ = 1/h, so its maximum over [μ, L] is attained at an endpoint and equals max(|1 − hμ|, |1 − hL|). Increasing h lowers the first and raises the second once hL > 1, so the maximum is smallest where they are equal. On the κ = 9 valley, h = 2/10 = 0.2, and the two coordinates are multiplied by 1 − 0.2 = 0.8 and 1 − 1.8 = −0.8 at every step. The steep coordinate flips sign each step while the flat one creeps toward zero, and the distance to the minimum shrinks by exactly 0.8 per step. Reaching one millionth of the starting distance takes about ln(106)/ln(1/0.8) ≈ 62 steps.

Fact

Gradient descent needs on the order of κ steps to gain each constant factor of accuracy. The whole subject of acceleration is the search for methods that need only on the order of √κ, which is a large saving when κ is in the thousands or millions.

In short: curvature spread κ forces gradient descent to rate (κ − 1)/(κ + 1) ≈ 1 − 2/κ, which is 0.8 on the running valley.

9 · ASSESSMENT

What is shown, and what isn't

What is shown is a complete picture for two-step methods in the large-κ limit. Upper bounds come from explicit certificates (nonnegative combinations of interpolation inequalities) and lower bounds from explicit functions built from spirals or periodic rotations, so the constants are exact rather than merely bounded. Several known constants are recovered (Nesterov's 2/3, TMM's 1) and some improved; for HNAG++ the squared-distance coefficient 4√2/3 improves the global coefficient √2 of its authors. The finite-κ threshold of Theorem 8.1 is exact and clean. Our own checks agree with the paper on every point we tested: Polyak's rate 1/2 and TMM's 2/3 on the valley, TMM's factorization of χμ and χL, the identity (9), and the Figure 3 claim that strict passage for (y, τ) = (1, 1/4) starts at K = 8.

The limits are mostly of scope. Almost all constants are asymptotic: o(κ−1/2) errors are not quantified, so the theorems do not say how large κ must be before, for example, Nesterov's worst case really is 1 − (2/3)κ−1/2. The exceptions are TMM's exact rate and the thresholds of Section 8. The rates are worst cases over the entire class, achieved by carefully built functions whose dimension can grow as the target precision improves; they say nothing about typical problems, and the paper does not claim they do. Some cases remain open: the arithmetic gap at the corner, whether accelerated methods with three or more steps of memory must have a nonnegative symbol at every frequency, the size of the worst-case dimension, and periodic or time-varying methods.

The paper states that all results have formal proofs in the Lean proof assistant, with a public repository; we did not inspect it. It also states that the authors used AI tools to assist with exposition, formal proof verification and literature checks, and that they verified the statements and take responsibility for them. It is a fresh preprint and has not been refereed.

A connection, oursMachine learning optimizers such as quasi-hyperbolic momentum are members of 𝓜 (Remark 4.4 gives the dictionary τ = (1 − ν)β/(1 − β)). The paper's Corollary 6.6(iii) implies that a fixed weight ν < 1 with β → 1 cannot accelerate even on quadratics, which is a precise version of the folklore that these optimizers behave like plain gradient descent unless tuned in a very particular way. The paper states the corollary; the folklore reading is ours.

In short: exact, certified and formalized for two-step methods as κ → ∞; asymptotic and worst-case by design, with a few precisely stated gaps.

Entropy Maximization for Cube Projections

Zhekai Pang · posted Nov 10, 2026 · math.PR · arXiv 2611.13533

Overview

Shine a light through a cube onto a line and the shadow of a uniformly random point is a weighted sum of independent uniform numbers; this paper proves that, in every dimension n ≥ 150, the shadow is most spread out, in the sense of Shannon's differential entropy, exactly when all the weights have the same size. The question was posed by Eskenazis, Nayar and Tkocz, and the proof has two halves of very different flavor. The first is a clean averaging argument that reduces the whole theorem to one sign: the third derivative of the logarithm of a single density must be negative. The second proves that sign with a trick from statistics called exponential tilting, which moves every point to the center of a reweighted distribution, followed by careful Fourier estimates in which a Gaussian approximation is made rigorous with explicit constants. The constants are what force the restriction n ≥ 150.

By the end you'll be able to explain
  • why every projection Σ aiUi with Σ ai2 = 1 has the same variance 1/3, and what differential entropy measures beyond the variance;
  • why the Gaussian has the most entropy for a given variance, and the one-line inequality behind it, which the paper reuses;
  • the "Robin Hood" step that replaces two weights by their root mean square, and why it raises the expectation of any even function whose third derivative is positive on the right;
  • how repeating that step drives every weight to 1/√n, and why the theorem then reduces to the sign condition (log qn)‴ ≤ 0;
  • exponential tilting: how reweighting a uniform variable by etu moves any point of the support to the mean, so a sign at every point becomes a sign at the origin;
  • how the derivatives of a density at 0 are integrals of its characteristic function, why the skewness E[Y3] must be kept as a factor, and where the number 150 comes from.

1 · PROJECTIONS OF A CUBE

What is a cube projection?

Pick a point uniformly at random from the cube [−1, 1]n. Its coordinates are independent and each is uniform on [−1, 1]. Now choose a direction, a unit vector a, and record only the component of the point along that direction. That number is the shadow of the random point on the line through a, and the question of the paper is which direction makes the shadow most random.

Definition · cube projection

For a ∈ ℝn with Σ ai2 = 1, the one-dimensional projection of the uniform distribution on the cube in direction a is the law of the random variable X = Σi aiUi, where U1, …, Un are independent and uniform on [−1, 1].

In words: a weighted sum of independent uniform numbers, with weights whose squares add to one.

In short: repeatedly averaging the largest and smallest squared weights converges to equal weights, the Robin Hood lemma makes E[−log qn] rise along the way, and Gibbs' inequality turns that into entropy, so everything reduces to (log qn)‴ ≤ 0.

5 · EXPONENTIAL TILTING

How can a sign at every point be checked at one point?

The condition must hold at every x in (0, √n), and near the edge of the support the density qn is tiny and far from Gaussian. 9 · ASSESSMENT

What is shown, and what isn't

What is shown is a complete, self-contained proof of the Eskenazis–Nayar–Tkocz conjecture for cube projections in every dimension n ≥ 150, including the equality case. All constants are explicit and every inequality in the chain is proved in the text or its appendices. The reduction in Section 2 makes the Bartczak–Nayar–Zwara criterion rigorous, including the boundary issues at ±√n. The analytic core is a careful, quantitative central limit argument that keeps the skewness as a factor, which is necessary because the quantity being signed tends to zero as the tilt vanishes. Our independent checks agree with the paper where we tested them: the trapezoid sign pattern and second moments at (0.8, 0.6), the values of E[Ut] and Var(Ut), the arithmetic of Eqs. 43, 44 and 51 at n = 150, and the heuristic ratio w‴(0)/w′(0) ≈ −5, which our n = 150 computation puts at about −4.96.

What is not shown is the conjecture for 3 ≤ n ≤ 149. The paper states its result only for n ≥ 150 and does not discuss small dimensions or say whether the derivative condition (5) holds there. For n = 2 the conjecture follows from our closed form in Section 2, but that is not in the paper. Whether the method can be pushed lower is a question of sharpening constants: Eq. 51 alone would close at n = 134, but the other estimates were stated only for n ≥ 150, and by the paper's count of continuous derivatives (pn has n − 2 of them) the condition only makes sense for n ≥ 5. The result is also specific to uniform summands: the tilting computations use the explicit form of K(t) = log(sinh t/t) and the one-sign-change structure of the tilted uniform.

The paper is a single-author preprint posted on November 10, 2026, and has not yet been refereed.

A connection, oursExponential tilting is the same reweighting that underlies the Esscher transform in actuarial science and the change of measure used to price options or to simulate rare events by importance sampling: multiply a density by etx, renormalize with the cumulant function, and a rare region becomes typical. Here it is used not to compute a probability but to transfer a sign from the edge of the support to its center.

In short: a complete and fully explicit proof for n ≥ 150; dimensions 3 to 149 remain open in the paper, and the method is tailored to uniform summands.

Loss of the Quadratic Speedup in Grover Search under Local and Coherent Noise

Imama Tul Birrah Khan, Muhammad Faryad · posted Nov 12, 2026 · quant-ph · arXiv 2611.16398

Overview

Grover's algorithm finds one marked item among N in about √N steps by turning a state vector through a small angle again and again, and this paper works out, in closed form, exactly how noise takes that rotation apart. The answer comes in three shapes. Noise that scrambles the whole register leaves the rotation untouched but shrinks the part of the state that is rotating, by a fixed factor per gate layer. Noise on individual qubits knocks amplitude out of the two-dimensional plane where the search happens, and a short geometric fact says that whatever leaves the plane is frozen there for good. Coherent errors in the rotation angle keep the state pure but blur where it points, by an amount that grows linearly with depth. All three lead to the same rule of thumb: the total error accumulated over the √N-deep circuit must stay of order one, which for errors on single qubits means a per-qubit error rate below about 1/(n√N), where n is the number of qubits.

By the end you'll be able to explain
  • why Grover's oracle and diffusion step are two reflections, why two reflections make a rotation by 2α with sin α = 1/√N, and where the π√N/4 iteration count comes from;
  • what a density matrix is, how a noise channel acts on one, and how bit flips, phase flips and depolarizing noise differ;
  • why a depolarizing channel on the whole register commutes with every gate, and how that gives the exact success probability Pr(pg) of Eq. 30;
  • why the best stopping point moves earlier under noise, and how the expected query cost goes from √N to about 2pgN;
  • why the Grover operator is just −1 off the search plane, and why that makes a phase flip most harmful early and a bit flip most harmful late;
  • how the in-plane part of the state obeys Bloch-type equations with leakage and dephasing rates, and where the noise budget p ≲ 1/(c n√N) comes from;
  • how bounded angle errors widen into a band of possible success probabilities that grows linearly with depth.

1 · SEARCHING WITHOUT STRUCTURE

What problem does Grover's algorithm solve, and how is it set up?

Suppose a function f on n-bit strings returns 1 on exactly one string w and 0 everywhere else, and the only way to learn anything about f is to evaluate it. A classical computer has no choice but to try strings one by one, so on average it needs about N/2 evaluations to find w. Grover's algorithm needs about (π/4)√N. For a million items that is roughly 785 queries instead of 500,000, and the paper notes that no quantum algorithm can do better. The point of the paper is to ask how much of this square-root advantage survives when the hardware is noisy.

The quantum computer holds a register of n qubits. Its state is a unit vector in an N-dimensional complex vector space, written in the basis of the N bit strings: |ψ⟩ = Σx cx|x⟩ with Σ|cx|2 = 1. Measuring the register returns the string x with probability |cx|2. Inner products ⟨φ|ψ⟩ = Σx conj(bx)cx work as for ordinary vectors, and an outer product |φ⟩⟨φ| is the matrix that projects onto |φ⟩. Gates are unitary matrices, which preserve lengths and angles.

In short: the register's state is a unit vector; the equal superposition |s⟩ sits at the small angle α = arcsin(1/√N) from the unmarked direction, inside a plane that contains the answer.

2 · TWO REFLECTIONS MAKE A ROTATION

How does each iteration move the state toward the answer?

The oracle is how the algorithm asks f a question. Instead of writing f(x) into a separate bit, it writes the answer into a sign: Uf|x⟩ = (−1)f(x)|x⟩ (Eq. 5). Only the marked state changes, and because the basis projectors sum to the identity, the oracle has a compact form.

Eq. 7

This is a reflection. It leaves every vector orthogonal to |w⟩ alone and reverses the component along |w⟩. In the Grover plane it flips the state across the |w⊥⟩ axis, sending an angle θ to −θ.

The second ingredient is the diffusion operator V = H⊗nU0H⊗n, where U0 = 2|0⟩⟨0| − I reflects about the all-zeros state (Eqs. 9 and 10). Since the Hadamard layer sends |0⟩⊗n to |s⟩, conjugating by it turns a reflection about |0⟩ into a reflection about |s⟩.

Eq. 11

In terms of amplitudes, V replaces each cx by 2m − cx, where m is the mean amplitude, so it is often described as inversion about the mean. After the oracle has made the marked amplitude negative, it sits far below the mean, and inverting about the mean lifts it far above.

derivationWhy is 2|s⟩⟨s| − I the same as inversion about the mean?

For any state Σcx|x⟩, the inner product ⟨s|ψ⟩ is Σcx/√N = √N m, where m is the mean amplitude. So 2|s⟩⟨s|ψ⟩ = 2√N m · (1/√N)Σ|x⟩ = Σ 2m|x⟩. Subtracting |ψ⟩ leaves Σ(2m − cx)|x⟩. Each amplitude is reflected through the value m.

∎

proofWhy does a reflection followed by another reflection give a rotation by twice the angle between their axes?

The paper's argument is geometric. Start at angle θ from |w⊥⟩. The oracle reflects across the |w⊥⟩ axis, to −θ. The diffusion step reflects across the line through |s⟩, which sits at angle α; reflecting an angle φ across a line at angle α gives 2α − φ. So −θ goes to 2α + θ. Each iteration adds 2α, and starting from θ = α gives (2r + 1)α after r rounds.

3 · DENSITY MATRICES AND NOISE

How do we describe a state that has been hit by random errors?

A state vector describes a register we know perfectly. Once errors strike at random, the register is in state |ψ1⟩ with some probability and |ψ2⟩ with another, and the right description is a weighted average of projectors. This is the density matrix, and the paper uses it from its first equation on.

Definition · density matrix

If the register is in state |ψi⟩ with probability qi, its density matrix is ρ = Σi qi|ψi⟩⟨ψi|. The probability of measuring x is the diagonal entry ⟨x|ρ|x⟩, and a gate U acts as ρ ↦ UρU†.

In words: a matrix whose diagonal holds the measurement probabilities (the populations) and whose off-diagonal entries (the coherences) record how much the components can still interfere.

For a pure state such as |s⟩ every coherence is as large as it can be. At the other extreme sits the maximally mixed state I/N, whose diagonal is uniform and whose coherences are all zero: it is the state of a register about which nothing is known, and measuring it gives a uniformly random string. Interference, the engine of Grover's algorithm, lives in the off-diagonal entries. Noise eats them.

On one qubit, any error between two gates can be expanded in the Pauli operators X (the bit flip, swapping |0⟩ and |1⟩), Z (the phase flip, negating |1⟩) and Y = iXZ (both at once). The general Pauli channel applies each with some probability.

Eq. 17

Three cases are standard. The bit-flip channel has (px, py, pz) = (p, 0, 0), the phase-flip channel (0, 0, p), and the depolarizing channel (p/3, p/3, p/3), which is the same as replacing the qubit by I/2 with probability 4p/3. The paper always compares channels at the same total error probability p, so that differences come from the kind of error and not its frequency.

A one-qubit example shows how differently X and Z treat the same state. Take |+⟩ = (|0⟩ + |1⟩)/√2, whose density matrix has all four entries equal to 1/2. A bit flip maps |+⟩ to itself, so the bit-flip channel leaves this state alone. A phase flip maps it to |−⟩ = (|0⟩ − |1⟩)/√2, so the phase-flip channel keeps the diagonal at 1/2 but multiplies the off-diagonal entries by 1 − 2p. Which error hurts depends on which state it hits. This simple observation, scaled up to n qubits, is the heart of Section 6.

The paper places a noise channel on every qubit after every gate layer: once after the initial Hadamard layer and, inside each iteration, after the oracle, after the first Hadamard layer of the diffusion step, and after U0. A circuit with r iterations therefore has 3r + 1 noise layers and n(3r + 1) chances for an error. This models both gate errors and idle decoherence.

In short: a density matrix stores populations on its diagonal and interference in its coherences; a Pauli channel applies X, Y or Z at random, and the paper puts one on every qubit after every gate layer, 3r + 1 layers in all.

5 · WHEN TO STOP, AND WHAT IT COSTS

How does noise change the best number of iterations and the cost of the search?

Once the success probability is known exactly, the practical questions are how high it can get, when to stop, and how many oracle queries a search costs on average. The answers depend on N and pg mainly through the product pg√N, which measures the noise accumulated over a full-length circuit.

Fact · the speedup has a horizon

Under global depolarizing noise the query cost follows the √N law while pg√N is small, and becomes linear in N, about 2pgN, once pg√N is large. The bend in the paper's Fig. 4 sits where pg√N reaches about one half, so the largest useful register is about nmax ≈ 2 log2(1/pg).

The linear regime is not a failure of the analysis but a known limit: the paper notes that lower bounds by Vrana, Reeb, Reitzner and Wolf and by Rosmanis show that any search against an oracle that depolarizes with fixed probability needs of order pN queries. Eq. 36 says Grover's algorithm, stopped at the right time and repeated, attains that bound with a small constant, keeping only a factor of about 4pg over a classical scan of half the database.

As a check on all of this, we evaluated Eq. 30 numerically at n = 16 and n = 20 (our computation). At n = 16 and pg = 0.0005, so pg√N = 0.128, the best count is 188, where Eq. 33 predicts 188.3. In short: noise pulls the best stopping point earlier by about 3pgN/8 and lowers the peak to about e−3πpg√N/4; once pg√N ≫ 1 the cost becomes about 2pgN, linear like classical search.

6 · LOCAL NOISE: WHAT ONE ERROR DOES

Why are some errors more harmful than others, and when?

Real errors strike individual qubits, not the whole register. Such errors do not commute with the gates, and they push the state out of the Grover plane. The paper's key observation is that the Grover operator treats everything outside the plane in the simplest possible way.

For a large database, drop the terms of order 1/√N and the picture becomes stark. A phase flip keeps the marked component, since Zk|w⟩ = ±|w⟩, but scrambles the signs of the unmarked component and throws it almost entirely out of the plane. A bit flip does the opposite: flipping one bit of an unmarked string almost always gives another unmarked string, so the unmarked component stays, while Xk|w⟩ is an unmarked basis state and leaves. A Y error throws out both. Either way the coherence between |w⊥⟩ and |w⟩ is gone.

Physical bit-flip noise therefore produces one bit-flip-like and two phase-flip-like events per iteration, and phase-flip noise the reverse.

In short: G = −1 off the plane, so whatever an error knocks out is lost; a phase flip keeps only the marked part (P ≈ sin4θ, worst early), a bit flip keeps only the unmarked part (P ≈ cos4θ, worst late), and each costs 5/8 of the success probability on average.

7 · THE GROVER PLANE AS A NOISY QUBIT

What happens when many errors accumulate?

One error at a time is instructive, but a real circuit sees errors everywhere. Because frozen amplitude stays out, it can be discarded, and the search is fully described by the 2 × 2 block of the density matrix that lives in the plane.

Two approximations close the description: frozen amplitude can return only if a later error undoes an earlier one on the same qubit, which the paper estimates at a fraction of order 1/n of two-error events and neglects, and the 1/√N terms of Eq. 38 are dropped. Within these, each noise layer simply multiplies A, B and C by survival probabilities. The unmarked weight A survives a layer if no qubit gets a Z or Y, probability (1 − pz − py)n. The marked weight B survives if no qubit gets an X or Y, probability (1 − px − py)n. The coherence C survives only if no qubit gets any error, probability (1 − p)n. A layer seen through the Hadamard conjugation swaps px and pz.

One layer per iteration sees the channel as it is; the other two see px and pz exchanged. For a large database α is small, so the iterations can be treated as continuous time t counted in iterations, with the rotation advancing the angle at the rate ω = 2α. 9 · COHERENT ROTATION ERRORS

What if every gate is precise in kind but slightly off in angle?

A second kind of error does not randomize the state at all. A miscalibrated oracle or diffusion step rotates the state by slightly the wrong amount, and such errors can have the same sign every time, so they add up. The paper models this as a worst case: the angle after each oracle may be off by at most δ, and the angle after each diffusion step by a further amount of at most Δ, with signs unspecified. 11 · ASSESSMENT

What is shown, and what isn't

What is shown exactly: the global depolarizing model is solved without approximation, and Eq. 30 is a true identity for the stated circuit (our 16 × 16 density-matrix simulation reproduces it to every digit we printed). The off-plane identity Eq. 37 and the in-plane Pauli matrices of Eq. 38 are exact for every N. The interval bookkeeping for bounded coherent errors, Eqs. 50 to 61, is exact under the stated worst-case model. The asymptotic formulas Eqs. 31, 33, 34 and 36 follow from Eq. 30 by standard expansions in clearly stated regimes, and our numerical checks at n = 16 and n = 20 agree with them.

What rests on approximations: everything about many local errors. The Grover-plane equations neglect amplitude returning to the plane (argued to be a fraction of order 1/n of two-error events), drop the 1/√N terms of Eq. 38, treat iterations as continuous time, and use first-order survival probabilities. So Eqs. 44 to 49 are leading-order statements for large N and small p, and the paper says as much. The single-error formulas Eqs. 39 and 40 are likewise large-N approximations; at N = 16 our simulation shows sizable deviations, though at N = 256 they are close. For bit-flip, phase-flip and amplitude-damping noise the paper describes the corrections from the population asymmetry δ as "a few percent" and "several percent" without tabulating them, and the amplitude-damping rates rest on a first-order argument given in prose. The noise budget in Fig. 6 comes from integrating Eq. 44, not from a simulation of the full n-qubit density matrix, so it inherits these approximations.

The model choices also matter. Noise follows every gate layer with the same strength, errors on different qubits and layers are independent, and the coherent-error analysis is worst case: it says how far the state can wander, not how far it typically does. Correlated and time-dependent noise are left to future work, as is error correction or mitigation. Much of the content is a unified, closed-form rederivation of scalings found before (Cohn et al., Long et al., Shenvi et al., Azuma); the new parts are the frozen-complement picture, the rates of Table 1 and the explicit constants. The paper is a two-author preprint posted on November 12, 2026, not yet refereed, and its acknowledgments state that an AI assistant was used to revise the text, check derivations and develop and extend analytical results.

A connection, oursThe same rotation picture powers amplitude amplification, the subroutine behind quantum speedups for Monte Carlo estimation (including option pricing proposals) and for some optimization heuristics. Any of these inherits the budget of this paper: the total noise over a √N-deep amplification circuit must stay of order one, which is one reason such speedups are usually discussed for error-corrected machines rather than today's devices.

In short: the global-noise and coherent-error results are exact under their models; the local-noise budget is a careful leading-order estimate that recovers known thresholds and adds explicit constants.
